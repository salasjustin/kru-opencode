# Official Sources Registry

**Team principle — official sources first.** For any framework / library / API / CLI / cloud-service specifics, no agent answers from training data. Resolve it through the official MCP, skill, or plugin below. Prefer first-party sources over third-party blogs. Training data is a starting hypothesis to verify, never the answer.

**Corollary — a repo-authored skill is the layer the docs can't serve.** Docs are hammer and nails; they don't make the house come out right the first time. So a skill here carries **recipes and patterns earned by working with the thing** — order that matters, defaults chosen after the obvious one failed, cases where correct-by-the-docs is wrong in practice, popular advice that's wrong. Anything derivable from the official source in the moment is a **lookup, not a skill**, and stays in that stack's row below. A skill that restates docs ages out of sync and then outranks the source while stale — which is why quickstart-grade community packs get rejected rather than vendored (see the Drizzle row). Authoring rules: `skill/kru-roster/author.md`.

Agents: consult the row for the stack you're working in. The PM (the `lead` skill) uses this table to route and to wire any newly-minted specialist to its official source.

**When a row's source is unreachable, say so and climb down — never answer from training data instead.** A source goes missing for two reasons, and a **cloud session** hits both at once: an MCP server added at user scope (`claude mcp add` with no `--scope project`) stays on the machine it was added on, and the default `Trusted` network level reaches package registries, GitHub and the cloud SDKs but **not** the doc domains this table names. The ladder, in order, each rung reachable where the one above it isn't:

1. **The installed package itself** — its `.d.ts`, its `README`, its source under `node_modules` (or `go doc`, `python -m pydoc` off the installed interpreter). The most version-pinned source there is, and it needs no network at all.
2. **The project's own `.mcp.json`** — a server committed there loads in a single-repo cloud session, unlike a user-scope one. Its traffic still leaves through the session's network, so the host needs to be on the allowlist.
3. **A claude.ai connector** — connector traffic goes through Anthropic's servers rather than the session's network, so it reaches the source whatever the network level says. Its tools arrive under a different prefix (`claude_ai_<Name>__*`) than the same server added with `claude mcp add`.
4. **The upstream repo over `raw.githubusercontent.com`**, which is on the default allowlist where the doc domain is not. Most of the doc sites in this table are generated from `.mdx` in a public repo.
5. **Say the source was unreachable** in the return, and name which rung answered. A version-specific claim resolved from memory is the failure this table exists to prevent, and it is invisible unless the return says so.
